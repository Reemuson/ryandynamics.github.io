The goal is not to run the entire design immediately. The goal is to see whether the power input and rails behave as expected without damaging the board. table: compact: true headers: [Step, What to check, Why] rows: - cells: [Set current limit, Start with a conservative limit, Reduces damage from shorts or wrong parts] - cells: [Apply input power, Watch supply current, Unexpected current is often the first fault sign] - cells: [Measure rails, Check each voltage rail, Confirms regulators and power sequencing] - cells: [Check heat, Carefully identify warming parts, Finds overloaded or misassembled components] - cells: [Power cycle, Confirm repeatable behaviour, Separates one-off startup events from real faults] - title: Bring up one function at a time body: >- Once the power rails are correct, the next step is controlled functional testing. It is better to prove each block separately than to run full firmware and try to debug everything at once. items: - { label: MCU basics, text: "Confirm programming access, reset behaviour, boot configuration, and clock setup." } - { label: GPIO, text: "Toggle known pins and verify they reach the expected connector or circuit node." } - { label: Inputs, text: "Check switches, analogue inputs, sensor rails, pull-ups, and filtering." } - { label: Communications, text: "Bring up UART, SPI, I2C, CAN, RS-485, or wireless interfaces one at a time." } - { label: Outputs, text: "Test LEDs, relays, MOSFETs, motors, and other loads with safe limits first." } - title: Typical faults found during bring-up table: compact: true headers: [Symptom, Possible causes] rows: - cells: [Supply current too high, "Shorted rail, wrong component, reversed IC, solder bridge"] - cells: [No firmware connection, "SWD/JTAG wiring issue, reset held low, wrong boot mode, no MCU power"] - cells: [Sensor not responding, "Address conflict, missing pull-ups, wrong voltage, bad footprint, bus held low"] - cells: [Output does not switch, "Gate/base drive issue, wrong pin mapping, missing flyback path, firmware configuration"] - cells: [Unstable readings, "Grounding, noise, ADC scaling, filtering, cable pickup, reference voltage issue"] - title: Good notes save time body: >- Bring-up is much easier when each test is recorded.
